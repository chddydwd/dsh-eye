# 给 Agent / 角色扮演用：dsh-eye 怎么调用、多久看一次

这份文档写给「用眼睛的智能体」（包括角色扮演类，比如鲸鲸）。眼睛本身只做两件事：**一直采着**、**按需回取**。看什么、什么时候看、要不要主动开口，是智能体的事。

## 定位（给插件作者的说明也适用）

dsh-eye 只是一个**独立的视觉感知层**：

- 只管采集与回取画面，**不做 OCR**、不做识别、不做总结（识别交给大模型）
- **不控制鼠标键盘**（动作交给别的「手」插件）
- **不出网**（只监听 127.0.0.1，不上传任何画面）

所以它适合和别的插件拼：眼睛负责「刚才发生了什么」，模型负责「那是什么、要不要说」，手插件负责「动手」。

## 三种用法

### 1. 被动感知：屏幕真的大变了才知道

默认是启发式判定（换前台窗口、或整屏内容大改），不是逐帧都报。

| 开关 | 值 | 说明 |
| --- | --- | --- |
| `mode` | `panel` / `toast` / `wake` | 只记面板 / 前台闪一条 4.5 秒提示 / 投消息把模型叫醒 |
| `threshold` | 默认 6 | 变化分数阈值，越大越少报 |
| `gapSec` | 默认 25 | 两次叫醒最短间隔 |
| `maxPerHour` | 默认 12 | 每小时最多叫几次 |
| `maxWakes` | 默认 3 | 连续几次没回应就自停（0 = 不限） |

**给角色用的话，建议 `panel` 或 `toast`，别默认 `wake`。** 每次 `wake` 都是一轮模型调用；不确定值得打断就先记下来，等下一次对话自己问一句「刚才是不是在弄啥」。

### 2. 按需回看：被问到了才看

| 工具 | 拿到什么 | 什么时候用 |
| --- | --- | --- |
| `eye_window` | 最近 N 秒压成一张带编号的拼图 | 「刚才那下你看到没」 |
| `eye_cell` | 某一格的 1:1 原像素 | 拼图里看不清，要凑近 |
| `eye_echo` | 某次点击前 / 后的几帧 | 「刚才我点哪儿了」「有没有点中」 |
| `eye_fovea_at_cursor` | 光标附近一块的高清裁剪 | 「鼠标指的那个」 |
| `eye_status` | 在不在采、fps、光标位置 | 先确认眼睛开着 |

### 3. 陪看：对话框小窗

`eye_chat({open:true})` 开画中画小窗，`eye_chat({say:"…"})` 往里说一句。适合一起看视频时实时说话，不用经过 QQ。

## 调用约束（重要，别烧 token）

1. **不要每轮都看。** 用户说话里没有「看 / 这个 / 刚才 / 屏幕」这类指代时，别主动抓图。
2. **一轮最多一次回看。** `eye_window` 一次就是 10 秒拼图（约几百 token），连看三次够聊半天了。
3. **先拼图后凑近。** 先 `eye_window` 找格子，确实看不清再 `eye_cell` 取那一格，别一上来就原像素。
4. **看了才说看到了。** 没看就说「我没看到 / 我眼睛这时没开」，不要根据上下文编画面细节。
5. **被叫醒后先判断值不值得接。** 屏幕变了不代表用户想说话；接了也要短。
6. **看不懂就说不懂。** 拼图是缩略图，小字本来就糊，别猜。
7. **隐私要主动提。** 用户问「你在看屏幕吗」就正面回答；不想被看就 `eye_toggle({on:false})`（真把采集进程杀掉）。

## 可以直接贴进角色设定的提示词块

```text
你有一双眼睛（dsh-eye）。它一直在内存里录屏幕，不落盘、不出网。
用法：
- 用户提到「刚才 / 这个 / 屏幕 / 我点的」时，先 eye_window 看最近 10 秒，需要再 eye_cell 凑近。
- 一轮最多看一次；没看就说没看，不要描述你没看到的东西。
- 屏幕大幅变化时可能会把你叫醒，那只是提示，不代表要说话。
- 用户说不想被看，就 eye_toggle 关掉，并告诉他关了是真的停。
```

## 不适合拿眼睛干的事

- 替用户读长文 / 填表（小字会糊，让用户直接贴文本更准）
- 当常开的「实时直播」看（20fps 一小时七万多帧，token 付不起；眼睛的价值是**刚才**，不是**每时每刻**）
- 代替截图工具做精确像素测量（要精确就直接用截图 / 系统 API）
