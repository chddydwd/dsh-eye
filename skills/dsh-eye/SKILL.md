# dsh-eye：怎么"看"这块屏幕

dsh-eye 是一个 DSH 插件：后台常驻采样，最近 45 秒的画面一直躺在内存里（不写盘）。它**不会动手**——只报坐标、只出图，点不点由你/用户决定。

## 0. 先判断：真的需要看图吗

| 用户的问法 | 用什么 | 成本 |
|---|---|---|
| "这上面写的什么字"、"这段报错是什么" | `eye_text` | ≈0（无障碍树；读不到才回落 OCR） |
| "那个按钮在哪"、"帮我找到输入框" | `eye_find` | ≈0（只给屏幕坐标） |
| "现在大概是什么界面/什么状态" | `eye_look` | 300–450 token |
| "这个字太小/图标是亮是灰/勾没勾上" | `eye_region` | ≈370 token |
| "刚才那个弹窗写了什么/我点了之后有反应吗" | `eye_frames` | ≈820 token |
| "我在不在录屏/眼睛开着吗" | `eye_status` | 0 |
| "看这个板 / 盯住那个框"（目标只占屏幕一小块） | 先 `eye_focus` 挪框，再 `eye_look` | 省一大截 |

**口诀：能读字就别取图；一屏看不清就凑近，不要用更宽的图硬看。** 图一旦进上下文，后面每一轮都会重读（缓存价约为原价 1/10），所以"少而准"比"多而全"省得多。

## 1. 三档取图工具

### `eye_look` —— 一屏全景
- 参数：`w` 320–1280（默认 768）、`q` 40–90（默认 68）
- 拿环里最新一帧，等比缩到宽 w，重编 JPEG
- token ≈ 宽×高÷750：768→442、640→307、1280→1229
- 回答"大概什么界面"；**看不清小字**。降 `q` 只省流量不省 token，降 `w` 才省（平方关系）。

### `eye_region` —— 凑近 1:1
- 参数：`fw` 200–1600（默认 700）、`fh` 120–1200（默认 393）、`cx`/`cy` 裁剪中心、`atCursor:true` 裁在鼠标处
- 最新帧里按原像素裁一块，**不缩放**，输出 PNG
- token ≈ 700×393→367
- 回答"这个字/这个图标/这个勾选框到底是什么"；坐标就是屏幕物理像素，跟 `eye_find` 返回的坐标同一套。

### `eye_frames` —— 回看刚才
- 参数：`span` 往回几秒 1–60（默认 10）、`n` 抽几格 1–12（默认 6）、`cols` 每行几格 1–6（默认 3）、`w` 表宽 480–1600（默认 1280）
- 从环里均匀抽帧拼成联络表：每格左上角黑底黄字编号 0..n-1，**最后一格是现在**
- token ≈ 1280×480→819
- 回答"刚才发生了什么"：弹窗内容、点击前后对比、操作顺序。
- 坑：屏幕闲着时只有 2fps，抽出来的帧会重复，"看起来没动"可能是采样假象；格子约 400×225，小字要再 `eye_region`/`eye_cell` 拉一块；快速动画会漏帧。

### `eye_focus` —— 先把取景框挪过去（不是取图工具，但最省钱）
- 用法：`eye_focus({title:"配置"})` / `{hwnd:123}` 绑窗口（跟着窗口走）；`{x,y,w,h}` 固定一块；`{clear:true}` 取消。
- **什么时候用**：用户说「看那个报错框 / 盯住这个面板 / 就看这块」，或者你要看的目标只占屏幕一小块。先定位再挪框：
  - 不知道是哪个窗口 → `eye_text`（读前台窗口名，免费）
  - 知道名字 → `eye_focus({title:"窗口标题里的一小段"})`
  - 要找控件 → `eye_find({q:"保存"})` 拿坐标，再给固定矩形
- 挪完框之后 `eye_look` / `eye_region` / `eye_frames` **自动只抓这块**：600×400 一块 = 320 token，1:1 原像素，小字比整屏缩图清楚。
- 不传参数 = 看现在聚焦在哪、抓多大。
- 一次任务结束就 `clear`：别让它一直锁在一个早就没用的窗口上。

## 2. 标准套路

**看一个不熟的界面**：`eye_look`（大局）→ 发现要看细的地方 → `eye_region({atCursor:true})` 或给 `cx/cy` → 需要原文再用 `eye_text`。

**盯一个小面板/一个框**：`eye_text` 或 `eye_focus({title})` 定位 → `eye_focus` 挪框 → `eye_look`（现在拿到的是这块的 1:1，小字也读得清）→ 完事 `eye_focus({clear:true})`。

**验收一次操作**：操作前 `eye_look` → 做动作（你自己点，或用户点）→ `eye_frames({span:10,n:6})` 看变化 → 不确定的那一格 `eye_region` 放大。

**读报错**：先 `eye_text`（免费）；它读不到（自绘界面/图片里的字）再 `eye_region` 裁报错框。

**屏幕坐标从哪来**：`eye_find({q:"保存"})` 给中心点；`eye_status` 给光标位置；`eye_echo` 给最近一次点击的前后四格。要真点，用 win32 那套工具，别用眼。

## 3. 会被拒的情况（被拒时图不生成、不扣 token）

| 返回 | 原因 | 怎么办 |
|---|---|---|
| `视觉取图关着（只读字、不出图）` | 视觉开关关了 | `eye_vision({on:true})` |
| `今天的看图预算用完了…` | 当日额度用尽 | 提额度 `eye_vision({budget:600000})`，或改用 `eye_text` |
| `眼睛是关着的（采集进程没起）` | 采集进程没起 | `eye_toggle({on:true})`，等约 2 秒 |
| `（拿到图了，但宿主没有 attachments 服务…）` | 宿主不支持附件 | 只能读字；这条提示本身就是证据 |
| 工具返回了图片但**你看不到图** | 插件 < 0.3.1，或宿主不会把 `images` 自动转成附件 | 升级到 0.3.1+；判定标准是"对话里真的出现了那张图"，不是"返回了 images 字段" |

## 4. 隐私与开关

- `eye_mask({rects:[{x,y,w,h}]})` 框住的地方在**进缓冲之前**就糊掉：既不出图、`eye_text` 也不读那里的字。银行/支付/密码类窗口按标题自动整窗糊。
- `eye_toggle({on:false})` 是真把采集进程杀掉，不是只藏窗口。
- 主动「看一眼」时这一帧会成为对话附件存在本机（跟别的附件一样），环形缓冲本身不写盘。
- 输出走本地 HTTP（`127.0.0.1:13201`），不上传任何服务器；模型看到的只是你主动取的那几张图。

## 5. 成本控制

- 单张 token ≈ 像素 ÷ 750；**文件大小（JPEG 质量）不影响 token**。
- 日预算默认 30 万 token，面板「视觉」那节能看用量/改额度/清零；`eye_vision()` 也能查。
- 想省：优先 `eye_text` → 目标明确就先 `eye_focus` 只抓那块（600×400 = 320 token，还更清楚）→ 再看 640 宽的 `eye_look` → 只放大真正可疑的那一块 → 回看用 `n=4` 而不是 12。
- 一次任务里反复看同一屏没有意义：看一次，记住结论。
